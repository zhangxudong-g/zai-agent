## 三、需要修正的本地错误/过时信息

### 🔴 错误 1：`写文件工具无干扰模式配置.md` 多处误导

**问题描述**：本文将 `file_editor` 描述为 "官方推荐"、且与 `editor` 工具并列对比，存在以下偏差：

1. **`file_editor` 并非通用文件编辑工具的"官方版本"**
   - 实际情况：`file_editor` 来自 `strands.vended_tools.file_editor`，**专用于 sandbox（如 DockerSandbox、PosixShellSandbox）环境**。
   - 源码佐证：`.venv/Lib/site-packages/strands/sandbox/docker.py:10` 中 `from ..vended_tools.file_editor import make_file_editor`，明确它在沙箱里被装载。
   - 在**非沙箱场景**下，`file_editor` 不会自动随 Agent 注册，必须配合 `sandbox=` 参数使用。

2. **`BYPASS_TOOL_CONSENT` 不是 Strands 核心 SDK 的环境变量**
   - 它属于 `strands-tools`（社区包），由 `.venv/Lib/site-packages/strands_tools/environment.py` 维护。
   - 官方核心 SDK 自身 **没有** 写入文件前需要确认的机制；确认机制只对 `strands_tools` 提供的工具（如 shell、file_write、python_repl）生效。
   - 所以示例 `Agent(tools=[editor])` + `BYPASS_TOOL_CONSENT=true` **仅在 `strands_tools.editor` 存在的前提下有效**；当前 0.8.6 实际安装中**没有 `editor` 子模块**（`ls strands_tools/` 显示 `file_editor/`、`shell/`、`http_request/`、`sleep/`、`_bash.py`，**没有 `editor.py`**），示例无法直接运行。

3. **`agent.tool.editor(command=...)` 的写法与实际 API 有出入**
   - `agent.tool.xxx()` 调用的是 `AgentTool`（`@tool` 装饰产物）；其入参取决于工具函数签名，而不是任意 `command=...`。
   - 例如 `strands_tools` 老版 `editor` 的 `command` 是工具内部 dispatch 字段，调用者直接传 `path/file_text` 等参数即可（取决于版本）。

**建议修订**：要么删除该文档，要么重写为《Sandbox 环境下 file_editor 使用指南》。

---

### 🔴 错误 2：`最大权限Agent配置.md` 中导入路径与现状不符

| 文档写法 | 实际情况（1.53.0） |
|---------|-------------------|
| `from strands.agent.conversation_manager import SummarizingConversationManager` | ❌ 真实路径是 `strands.agent.conversation_manager.summarizing_conversation_manager.SummarizingConversationManager`（子模块），顶层命名空间不再 `__init__.py` 中暴露 |
| `from strands.agent.conversation_manager.sliding_window_conversation_manager import SlidingWindowConversationManager` | ✅ 这个路径是对的 |
| `from strands.event_loop._retry import ModelRetryStrategy` | ✅ 这个对（`strands/__init__.py` 实际已导出 `ModelRetryStrategy`） |
| `from strands.tools.executors import ConcurrentToolExecutor` | ✅ 在 1.53.0 中可见（需要复核 `__init__.py` 是否导出） |
| `from strands.types.agent import ConcurrentInvocationMode` | ⚠️ 应为 `strands.types.agent`（顶层 types）；但实际枚举所在路径需 `python -c "from strands.types.agent import ConcurrentInvocationMode"` 验证 |
| `from strands.sandbox import DockerSandbox, ProcessSandbox` | ⚠️ 实际当前安装只看到 `Sandbox`、`PosixShellSandbox`；`DockerSandbox` 在 1.53.0 中需要确认 |
| `concurrent_invocation_mode="UNSAFE_REENTRANT"`（字符串） | 实际参数是 `ConcurrentInvocationMode` **枚举**，不是字符串 |
| `checkpointing=False` | ✅ 实际 `__init__` 签名中有此参数 |

**结论**：本文可作为概念参考，但代码示例 100% 不能直接 copy-paste 跑通。建议改为"概念性说明 + 引用官方文档"，不要贴完整可运行代码。

### 🟡 待补充 1：缺少 `callback_handler` 用法

`Agent工作原理分析.md` 提到回调处理器机制，但未给出 `logging.getLogger` + 自定义 callback 的官方推荐写法。建议新增：

```python
import logging
logger = logging.getLogger("my_agent")

def my_callback(**kwargs):
    if "data" in kwargs:
        logger.info(kwargs["data"], end="")
    elif "current_tool_use" in kwargs:
        tool = kwargs["current_tool_use"]
        if tool.get("name"):
            logger.info(f"[tool: {tool['name']}]")

agent = Agent(tools=[...], callback_handler=my_callback)
```

### 🟡 待补充 2：缺少 Debug 日志开启方式

```python
import logging
logging.getLogger("strands").setLevel(logging.DEBUG)
logging.basicConfig(format="%(levelname)s | %(name)s | %(message)s",
                    handlers=[logging.StreamHandler()])
```

### 🟡 待补充 3：缺少 `AgentResult` 字段详解

官方列出 `accumulated_metrics`、`accumulated_usage`、`tool_usage`、`total_cycles`、`total_duration`、`traces`、`average_cycle_time`。当前本地文档只提概念。

### 🟡 待补充 4：`最大权限Agent配置.md` 中 `interrupts` 字段与官方 API 漂移

官方 quickstart 提到的 "Interrupt 响应" 走 `{"interruptResponse": {...}}` 字典形式（见 `工具执行确认_ELI5.md`）。但 1.53.0 实际 API 是 `InterruptHandler`/`InterventionRegistry`（在 `strands.interventions`），不再是传 dict。
