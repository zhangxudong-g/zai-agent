# 📝 文件写入工具的正确使用方式

> ⚠️ **本文档已修订 (2026-08-26)**：原版将 `editor` 描述为"需要确认"、`file_editor` 描述为"官方推荐无确认"，与 Strands 1.53.0 实际不符。本文档按 SDK 现状重写。

---

## 🔑 关键结论

1. **核心 SDK (`strands-agents`) 本身不提供文件写入工具** —— 它只提供 `@tool` 装饰器，让你自己写。
2. **`strands_tools.editor` 已废弃** —— 0.8.6 中标记 `@deprecated`，迁移路径明确指向 `strands.vended_tools.file_editor`。
3. **`strands.vended_tools.file_editor` 专用于 Sandbox 环境** —— 它通过沙箱路由（`make_file_editor`）生成；在非沙箱场景下用同样的 API，但走本地文件系统。
4. **`BYPASS_TOOL_CONSENT` 是 `strands-tools` 社区包的开关** —— 只对 `file_write`/`shell`/`cron`/`http_request`/`load_tool` 等社区工具有效，对 vended/file_editor **无效**。
5. **`file_editor` 本身没有"确认对话框"机制** —— 它就是直接执行的命令式工具（`view`/`create`/`str_replace`/`insert`/`undo_edit`）。

---

## 📦 三种文件工具的关系

| 工具 | 来源 | 是否需确认 | 适用场景 | 状态 |
|------|------|-----------|---------|------|
| `@tool def write_file(...)` | 自定义 | 你自己实现 | 通用，按需加确认 | ✅ 推荐 |
| `strands_tools.file_write` | 社区包 | ✅ 有（可 BYPASS） | 想用社区实现且能接受 Rich 终端 | ✅ 可用 |
| `strands_tools.editor` | 社区包 | ✅ 有（可 BYPASS） | — | ⚠️ **已废弃** |
| `strands.vended_tools.file_editor` | vended（核心） | ❌ 无确认 | Sandbox 路由（DockerSandbox、PosixShellSandbox） | ✅ 当前推荐 |

---

## ✅ 方式 1：自定义 `@tool`（最灵活，**生产推荐**）

**优点**：行为完全可控、可以挂你自己的 hook/sandbox、与官方架构契合。

```python
import os
from pathlib import Path
from strands import Agent, tool

WORKSPACE = os.environ.get("AGENT_WORKSPACE", "./workspace")
WORKSPACE = str(Path(WORKSPACE).resolve())

@tool
def write_file(path: str, content: str) -> str:
    """写入文件到工作区。"""
    target = (Path(WORKSPACE) / path).resolve()
    # 沙箱式校验
    if not str(target).startswith(WORKSPACE):
        return f"Error: 拒绝写入 {target}（越界）"
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(content, encoding="utf-8")
    return f"已写入 {target}"

@tool
def read_file(path: str) -> str:
    """读取文件。"""
    target = (Path(WORKSPACE) / path).resolve()
    if not str(target).startswith(WORKSPACE):
        return f"Error: 拒绝读取 {target}（越界）"
    return target.read_text(encoding="utf-8")

agent = Agent(tools=[read_file, write_file])
result = agent("把 README 的标题改成 'Hello Strands'")
```

> 💡 这就是 `src/strands_poc/tools.py` 的实际做法（PoC 已经在用）。

## ✅ 方式 2：`strands.vended_tools.file_editor`（沙箱场景）

`file_editor` 是**命令式**工具：一个函数 + `command` 参数 dispatch。

### 2.1 在 Sandbox 中自动注册

`Sandbox` 是抽象类；`PosixShellSandbox` 也是抽象类（需要子类实现 `execute_streaming`）。
**可直接使用的具体实现**：`DockerSandbox`（容器内执行）、`SshSandbox`（远程主机执行）。

```python
from strands import Agent
from strands.sandbox.docker import DockerSandbox  # 或 strands.sandbox.ssh.SshSandbox

sandbox = DockerSandbox(container="my-agent-container")  # 需要已有运行的容器
# DockerSandbox 自动调用 make_file_editor 注册 file_editor 工具

agent = Agent(sandbox=sandbox, tools=[])  # 工具由 sandbox 自动注入
agent.tool.file_editor(command="view", path="/etc/hostname")
```

源码佐证：`.venv/Lib/site-packages/strands/sandbox/docker.py:10` 中
`from ..vended_tools.file_editor import make_file_editor` —— Sandbox 启动时自动注册。

**如需本地 Shell 子进程隔离**，自己实现一个 `PosixShellSandbox` 子类（提供 `execute_streaming`）。

### 2.2 在非沙箱场景下手动注册

```python
from strands import Agent
from strands.vended_tools import file_editor  # ✅ vended 工具

agent = Agent(tools=[file_editor])

agent.tool.file_editor(command="view", path="./README.md")
agent.tool.file_editor(command="create", path="./hello.txt", file_text="Hi\n")
agent.tool.file_editor(
    command="str_replace",
    path="./hello.txt",
    old_str="Hi",
    new_str="Hello",
)
agent.tool.file_editor(
    command="insert",
    path="./hello.txt",
    insert_line=1,                # 行号或搜索文本
    new_str="--- new line ---\n",
)
agent.tool.file_editor(command="undo_edit", path="./hello.txt")
```

**支持的命令**（来自 `.venv/Lib/site-packages/strands/vended_tools/file_editor/file_editor.py`）：

| `command` | 额外参数 | 说明 |
|-----------|---------|------|
| `view` | `path`, `start_line?`, `end_line?` | 查看（可指定行范围） |
| `create` | `path`, `file_text` | 创建文件（已存在则报错） |
| `str_replace` | `path`, `old_str`, `new_str` | 精确字符串替换 |
| `insert` | `path`, `insert_line`, `new_str` | 在指定行后插入 |
| `undo_edit` | `path` | 撤销上一次编辑（基于备份） |

**注意**：
- `file_editor` **没有确认对话框**，所以本文档标题里的"无干扰模式"对它来说是默认行为，不需要 `BYPASS_TOOL_CONSENT`。
- 它使用本地文件备份实现 `undo_edit`，**不是 git 级版本控制**，只回退一步。

## ⚠️ 方式 3：`strands_tools.file_write`（社区包，**需要确认**）

**先看版本警告**：`strands_tools.file_write` 是一个**未装饰的原始函数**，Agent 无法直接识别为工具。
最简用法：用 `strands_tools.load_tools` 或 `importlib` 加载；或自己用 `@tool` 包一层。

```python
import os
os.environ["BYPASS_TOOL_CONSENT"] = "true"  # 跳过确认

from strands import Agent, tool
from strands_tools.file_write import file_write as _file_write_func  # 原始函数

# 用 @tool 装饰器包一层，让 Agent 能识别
@tool
def file_write_tool(path: str, content: str) -> str:
    """写入文件内容。

    Args:
        path: 目标文件路径
        content: 要写入的内容
    """
    return _file_write_func(path=path, content=content)

agent = Agent(tools=[file_write_tool])
result = agent.tool.file_write_tool(path="./hello.txt", content="Hello")
```

**为什么需要包一层**：看 `strands_tools/file_write.py`：
- `calculator.py` 用 `@tool` 装饰（✅ Agent 可识别）
- `file_write.py` 是**裸函数**（⚠️ Agent 报 "unrecognized tool specification"）

> 💡 **常见误用**：`from strands_tools import file_write` 拿到的是**模块**而不是工具函数。
> 工具函数要从子模块导入：`from strands_tools.file_write import file_write`，或用模块下的 `TOOL_SPEC` 字典访问元信息。

**确认机制来源**：`strands_tools/file_write.py:195`
```python
strands_dev = os.environ.get("BYPASS_TOOL_CONSENT", "").lower() == "true"
```

**适用**：想在终端手动确认每个写入的交互式场景。

**不适用**：CI/CD、批量任务、自动化 —— 必须设置 `BYPASS_TOOL_CONSENT=true`，但 Rich 库的确认对话框在非交互终端会**卡住**！

## ❌ 弃用警告：`strands_tools.editor`

`strands_tools/editor.py:48` 明确警告：

```
_DEPRECATION_MESSAGE = (
    "editor is deprecated. This warning becomes an error log in v0.9.0. "
    "Migration path: use the file_editor tool vended by strands-agents "
    "(from strands.vended_tools import file_editor)."
)
```

**不要在新代码中使用 `from strands_tools import editor`**。

## 🧪 快速自检脚本

跑一遍确认你用的是当前版本正确的 API：

```python
# tests/test_file_tool_imports.py
from strands import Agent, tool
from strands.vended_tools import file_editor          # ✅ vended（直接是 AgentTool）
from strands_tools.file_write import file_write as _raw_fw
from strands_tools.file_write import TOOL_SPEC as FW_SPEC

# 社区 file_write 是裸函数，需 @tool 包一层
@tool
def file_write_tool(path: str, content: str) -> str:
    """写入文件。"""
    return _raw_fw(path=path, content=content)

assert file_editor.tool_spec["name"] == "file_editor"
assert FW_SPEC["name"] == "file_write"

agent = Agent(tools=[file_editor, file_write_tool])
print("Registered tools:", list(agent.tool_registry.registry.keys()))
# 输出: ['file_editor', 'file_write_tool']
```

## 📋 推荐配置组合

| 场景 | 推荐方案 |
|------|---------|
| **生产 PoC** | 自定义 `@tool write_file/read_file` + 路径沙箱校验 |
| **Sandbox（Docker/Posix）** | 让 Sandbox 自动注入 `file_editor`，直接 `agent.tool.file_editor(...)` |
| **快速交互式终端** | `strands_tools.file_write` + `BYPASS_TOOL_CONSENT=true` |
| **CI/批处理** | 自定义 `@tool` —— 永远不要依赖 Rich 终端确认 |
