# 🔄 幂等性 Token 去重是什么？

> 就像奶茶店的"叫号系统"！

---

## 🍵 奶茶店的故事

想象你去一家很火的奶茶店...

### 第一天：普通排队

```
👤 你：老板，来杯奶茶！
👨‍🍳 老板：好的，请等10分钟！

    （老板开始做奶茶...）
    （等了10分钟...）

👨‍🍳 老板：好了！请拿奶茶！
👤 你：谢谢！（开心地喝奶茶）🍵
```

### 第二天：神奇的"叫号卡"

这家奶茶店有个规矩：
> 🎫 每个人进店时都要领一张"叫号卡"
> 卡上有个号码，同一个号码只能做一杯奶茶

```
👤 你：进店，领到叫号卡（号码：888）
👤 你：老板，来杯奶茶！
👨‍🍳 老板：好的，卡号 888，10分钟！

👤 你（突然又想要一杯）：老板，再来一杯！
👨‍🍳 老板：你已经排上了，888号还在做呢！
👤 你：哦对！（乖乖等待...）
    （10分钟后...）

👨‍🍳 老板：888号，两杯奶茶好了！
👤 你：咦？我只拿到一杯奶茶啊？
👨‍🍳 老板：你的卡号是 888，只做一杯，给你了！
👤 你：...好吧！😅
```

---

## 🔑 这就是"幂等性 Token 去重"！

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   🎫 Token（叫号卡） = 用来区分"你是不是同一个人"的标记     │
│                                                             │
│   🔄 去重 = 同一个 Token 只能触发一次真正的操作              │
│                                                             │
│   🎯 效果 = 防止重复下单、重复支付、重复处理！              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 💻 在代码里是怎样的？

### 没有 Token 去重（会出问题）

```python
# 场景：用户疯狂点按钮，同时发了3个请求
# ❌ 没有去重 = 3杯奶茶！💸💸💸


async def order奶茶_没有去重():
    await 扣钱()  # 💸 扣了 30 块！
    await 下单()  # 📦 下了 3 单！
    await 通知()  # 📱 发了 3 条通知！
    return "下单成功"
```

### 有 Token 去重（完美！）

```python
# 场景：用户疯狂点按钮，但用的是同一个 token
# ✅ 有去重 = 只做 1 杯奶茶！🎉


async def order奶茶_有去重(token="888"):
    # 第一次看到 888 这个 token
    if not self._concurrency.is_registered(token):
        # 真正去排队！
        self._concurrency.register(token)

        await 扣钱()  # 💸 只扣 10 块！
        await 下单()  # 📦 只下 1 单！
        await 通知()  # 📱 只发 1 条通知！

        result = "下单成功"
        # 告诉其他"888号"请求：结果在这里！
        self._concurrency.complete(token, result=result)
        return result

    # 第二次、第三次看到 888
    else:
        # "你的888号正在做呢，等一下！"
        waiter = await self._concurrency.get_waiter(token)
        await waiter.wait()

        # 直接拿第一次的结果！
        return self._concurrency.get_result(token)
```

## 🎯 代码中的 Token 去重机制

源码位置：`agent.py` 的 `stream_async` 方法

```python
async def stream_async(self, prompt, idempotency_token=None, ...):
    
    # 第一步：申请进入
    begin = self._concurrency.begin(idempotency_token)
    
    # 如果有其他"同样token"的请求在执行中...
    if begin.waiting_on is not None:
        
        # 等待那个请求完成
        await begin.waiting_on.register_waiter()
        
        # 如果原请求出错了
        if begin.waiting_on.error is not None:
            raise begin.waiting_on.error  # 告诉我也出同样的错
        
        # 如果原请求成功了
        if begin.waiting_on.result is not None:
            # 直接把结果给我！
            self.callback_handler(result=begin.waiting_on.result)
            yield AgentResultEvent(result=begin.waiting_on.result).as_dict()
        
        return  # 完成！
    
    # 如果没有重复，说明是第一个请求
    if not begin.lock_acquired:
        raise ConcurrencyException("并发调用被拒绝")
    
    # ... 正常执行 ...
```

## 🤔 为什么需要这个机制？

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  实际问题：                                                 │
│                                                             │
│  🐛 网络不稳定时，用户可能重复点击                            │
│  🐛 前端没做好，可能发送多个请求                             │
│  🐛 用户手抖，点了好几次                                    │
│                                                             │
│  没有去重会怎样？                                           │
│                                                             │
│  ❌ 重复扣款                                               │
│  ❌ 重复下单                                               │
│  ❌ 重复创建用户                                            │
│  ❌ 系统压力翻倍                                            │
│                                                             │
│  有去重就安全了！                                           │
│                                                             │
│  ✅ 只有第一个请求真正执行                                   │
│  ✅ 其他请求都乖乖等待，然后拿到同一结果                      │
│  ✅ 用户体验更好（不会看到错误）                             │
│  ✅ 系统更安全（不会重复操作）                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 📝 小结

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   🔑 Token 去重 = 同一个标记，只做一次真正的事              │
│                                                             │
│   🎫 Token = 用来识别的标记（可以是任意值）                  │
│                                                             │
│   🔄 去重原理：                                             │
│                                                             │
│   1️⃣ 第一个请求：发现没注册 → 真正执行 → 记住结果           │
│                                                             │
│   2️⃣ 后续请求：发现已注册 → 等待 → 拿第一个的结果          │
│                                                             │
│   ✅ 好处：防止重复操作，提升用户体验                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 🎉 现在你懂了！

**幂等性 Token 去重** 就是：

> 🎫 同一张"叫号卡"，只做一杯奶茶！
> 
> 🔄 后面来的人，都乖乖等第一杯，然后拿走同一杯！
> 
> 💰 不管点多少次，只扣一次钱！
> 
> 📱 不管发多少请求，只下一单！
